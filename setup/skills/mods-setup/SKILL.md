# MOD 설치 마법사

흐름 = 감지·가져오기 → 모드 → 고르는 칸 → 봇 → 요약 표 확인 → 한 번에 설치 → 점검 표 → 터미널 열기. 사용자는 비개발자일 수 있습니다 — 쉬운 우리말로, 한 번에 한 가지만 묻습니다.

## 먼저 지킬 것
- **토큰·비밀번호는 묻지도 받지도 않습니다.** Bash 도구엔 숨김 입력이 없어서, 토큰은 맨 끝에 열리는 터미널에서 사용자가 직접 넣습니다(`slackmod set-token`). 사용자가 채팅에 토큰을 붙이면 «여기엔 넣지 마세요 — 마지막에 열리는 창에서 넣습니다» 라고 하고 그 값은 어디에도 쓰지 않습니다.
- **다른 에이전트의 원래 설정은 읽기만 합니다.** 가져오기는 «사본»(`~/.slackmod/import/<시각>/` 와 봇 폴더의 프로젝트 범위 `.claude/`)이고, 원본 지문이 전후 같다는 줄을 `import.sh` 가 찍습니다 — 그 줄을 사용자에게 보여 줍니다.
- 질문은 `AskUserQuestion` 한 번에 **질문 4개 이하 · 질문마다 선택지 2~4개**. 자유 입력(채널 ID 등)은 일반 대화로 물어 답을 기다립니다.
- 홈 폴더 밖·`~/.slackmod` 밖(봇 작업 폴더 제외)에는 쓰지 않습니다. `sudo` 는 부르지 않습니다.
- 막히면 이유 한 줄 + 다음에 할 한 줄을 말하고, 막히지 않은 다른 칸은 계속합니다.

## 0. 경로 정하기 (처음 한 번)
저장소 폴더 `REPO` 를 정합니다: 환경 변수 `MODS_SETUP_REPO` 가 있으면 그것, 없으면 현재 폴더에서 위로 올라가며 `setup/.claude-plugin/plugin.json` 이 있는 첫 폴더. 그다음 `SETUP=$REPO/setup`, 설치 본체는 `INSTALLER=$(bash "$SETUP/lib/find-installer.sh" "$REPO")`(공개판 `<REPO>/slackmod/install.sh` → 없으면 개발판 `<REPO>/port/install.sh`). Bash 도구는 호출마다 변수가 사라지므로 **절대 경로를 알아낸 뒤 이후 명령에는 그 절대 경로를 그대로 적습니다.** 못 찾으면 «저장소 폴더에서 `bash install.sh` 로 다시 시작해 주세요» 하고 멈춥니다.

## 인자 읽기
`--answers FILE` → 아래 «답 파일 모드». `--section NAME` → 아래 «칸 하나 다시». 둘 다 없으면 1번부터.

## 1. 감지·가져오기 (먼저)
`bash "$SETUP/lib/detect.sh"` 를 돌려(읽기만) 나온 JSON 의 `items` 를 표로 보여 줍니다: 종류 · 이름 · 짧은 설명. 항목이 0개면 «가져올 기존 설정이 없습니다» 하고 2번으로.
있으면 `AskUserQuestion` 으로 «사본으로 가져올까요?» — 선택지: **전부 가져오기** / **고르기** / **안 가져오기**. 고르기면 항목을 몇 번 묶음으로 나눠 다시 묻습니다. 고른 `id` 들을 `import.from` 으로 기억합니다(여기서는 아직 복사하지 않습니다 — 복사는 7번 «설치 실행» 첫 단계).
`skipped` 가 있으면 «읽지 못한 것: …» 한 줄로 알립니다(고치라고 강요하지 않음).

## 2. 모드 3
`AskUserQuestion`: **빠른**(추천 기본값 그대로 · 아래 칸은 Slack 연결 정보와 ⑨ 하위 세션 쓰기 · ⑨-1 하위 라우터만 묻습니다) / **전체**(칸마다 고르기) / **빈 판**(설치 틀만, 봇 0개). 빈 판이면 3번은 «창 도구» 한 칸만 묻고 4·5번(봇)은 건너뜁니다.

## 3. 고르는 칸 10개(⑨-1 포함 · 전체 모드 = 세 번에 나눠 묻기)
추천값이 기본입니다(빠른 모드는 아래 «기본» 그대로 두고 ②의 연결 정보와 ⑨ · ⑨-1 만 묻습니다 — 둘은 질문 2개짜리 `AskUserQuestion` 하나).

**첫 번째 묶음(질문 4개)**
- ① 창 도구 — `tmux`(정식·기본 추천) · `cmux`(cmux 창 안에서 tmux) · `herdr`(그 안 tmux + 하위 탭) · `Orca`(시험 중 — «따로 설정하는 안내만» 드립니다, 자동 연결 안 함). 기본 = 자동(고르지 않음).
- ② Slack 연결 — **지금 연결** / **건너뛰기**(나중에 `--section slack`) / **Discord·Telegram·iMessage**(1판은 Slack 만 — 안내만 하고 건너뛴 것으로 처리).
- ③ 위키 — **Obsidian 폴더 지정** / **없음**(기본).
- ④ MCP — **위키 검색** / **없음**(기본).

**두 번째 묶음(질문 4개)**
- ⑤ 코덱스 — **끔**(기본) / **켬**.
- ⑥ 점검 스킬 — **넣음**(기본) / **안 넣음**.
- ⑦ 브라우저 — **playwright**(기본) / **aside** / **안 씀**.
- ⑧ 메모리 — **나중에**(기본) / **Hindsight** / **Kumiho**.

**세 번째 묶음(질문 2개 · 빠른 모드도 이것은 묻습니다)**
- ⑨ 하위 세션 쓰기 — **켬**(기본 추천) / **끔**. 추천 이유 한 줄: «여러 단계 일을 스레드마다 따로 맡기는 것이 이 봇의 기본 방식이고, 지금까지 깔린 봇도 모두 켬으로 돕니다 — 끔은 하위 창을 띄우기 버거운 작은 컴퓨터나 창 하나만 원할 때».
  - 고른 뒤 한 줄로 알립니다. **켬**: «봇이 일 크기를 보고 스스로 하위 세션을 열고, 연 스레드에 «하위 세션이 맡았어요» 한 줄을 남깁니다(기본 여는 글) · 하위를 열게 할 수 있는 사람 = 주인 <②의 사용자 ID, 없으면 «아직 없음 — Slack 연결 때 정함»>(과 허용한 동료 봇) · 손님 글로는 열지 않음 · 주인이 «하위로» 라고 써서 넘기는 말은 이 판에선 아직 안 됨(하위가 스레드에 직접 못 쓰기 때문 — 봇이 일 크기를 보고 엽니다)». **끔**: «봇에 하위 세션 도구(열기·목록·닫기·말 전하기·보드 요약)를 아예 넣지 않고, 모든 일을 봇 본 창에서 합니다 · 하위 세션을 열어 달라는 말엔 «하위 세션 없이 설치됐어요» 라고 답합니다».
- ⑨-1 하위 라우터(판정 모델이 고름) — **끔**(기본 추천) / **기록만** / **켬**. 이 칸은 늘 보입니다(판정기가 아직 없어도). 한 줄 설명: «주인이 봇에게 쓴 글이 다른 스레드에서 일하는 하위 세션의 일이면, 판정 모델이 그 하위를 골라 줍니다 — 기록만 = 고르기만 하고 기록(아무에게도 안 넘김) · 켬 = 고른 하위에게도 넘김(봇도 그 글을 그대로 받음)».
  - ⑨가 **끔**이면: «하위 세션이 없으니 하위 라우터도 꺼 둡니다» 한 줄 · `router.mode` = off.
  - ②의 주인 사용자 ID 가 없으면(건너뛰기): «주인 ID 가 없어서 켜도 돌지 않습니다(판정은 주인 글에만) — Slack 연결 때 함께 켜세요» 한 줄.
  - **기록만 · 켬**이면 후속 질문 `AskUserQuestion` «판정기» — **동봉 판정기 쓰기**(늘 보임) / **내 판정 명령 넣기**.
    - 동봉 판정기: «키는 마법사에 넣지 말고 터미널에서 `slackmod set-judge-key <봇>` 으로 넣으세요(화면에 안 보임 · 봇 slack 폴더의 route-judge.key 0600 · 봇 환경엔 안 들어감). 판정 1번 = Claude API 호출 1번(claude-haiku-5-5 · 몇백 토큰 · 주인 글과 하위 설명이 그 API 로 나감) · 5초 안에 답이 없으면 그 글은 판정 없이 봇이 받습니다 · 같은 계정의 프로그램은 키 파일을 읽을 수 있으니 판정 전용으로 한도를 건 키를 권합니다» → `router.judge` = `"bundled"`.
    - 내 판정 명령: 명령 낱말을 묻고(첫 낱말 = 프로그램 · 셸 없이 그대로 실행 · 키·토큰은 명령에 넣지 않음 — 넣으면 plan.py 가 거부), 꼴을 쉬운 말로 알립니다: «봇이 이 명령을 실행해 표준 입력으로 JSON 하나 `{v, boundary:"route1", body: 주인 글, dm, criteria: {"부모": 설명, "하위 A": 설명, …}, timeout_s}` 를 주면, 표준 출력 한 줄 `{"ok": true, "probs": {"부모": 0.1, "하위 A": 0.9, …}}`(모든 칸 0~1) 로 답합니다 · 못 고르면 `{"ok": false, "reason": "…"}` · 1.5초 안에 답이 없으면 판정 실패 = 봇이 그대로 받음» → `router.judge` = 낱말 목록.
  - 넘기는 규칙(고정): 한 하위가 0.85 이상 · 둘째 0.10 이하 · 부모 0.10 이하일 때만 넘깁니다(애매하면 봇 몫).

후속 질문(일반 대화):
- ② 지금 연결이면: Slack **채널 ID**(C 로 시작 · 채널 상세 맨 아래)와 봇에게 말할 **사용자 ID**(U 로 시작 · 프로필 ⋯ → 멤버 ID 복사)를 묻습니다. 모양이 틀리면(`^[CG][A-Z0-9]{8,12}$` · `^[UW][A-Z0-9]{8,12}$`) 다시. 선택으로 **손님** ID(여러 명 · 비워도 됨 — 손님 글은 «대화·답»만 받고 파일 쓰기·명령은 주인 글만)도 묻습니다. 토큰은 묻지 않습니다. 사용자 ID 를 넣으면 «주인 DM 스레드에서 봇이 답할 때 맨 앞에 주인 태그를 붙입니다(이미 있으면 그대로)» 한 줄을 알립니다(끄기 = 설정 `owner_tag: false`).
- ③ 폴더 지정이면 경로를 묻고 `test -d` 로 확인합니다(없으면 다시).

**이 칸들이 실제로 하는 일**(사용자에게 한 줄로 알려도 좋음): ⑨-1 하위 라우터 = 기록만·켬이면 봇의 하위 세션 플러그인 설정(`harness.json`)에 `session.jev_route`(하위 라우터 판정 명령 칸 · 동봉이면 그 명령에 봇의 키 파일 자리 `--key-file …/route-judge.key` 만 — 값은 터미널에서 · 봇 실행 줄엔 키가 없음), 끔이면 설치 파일이 지금과 똑같음 · ⑨ 하위 세션 쓰기 = 끔이면 같은 설정에 `session.children: false` 와 하위 없는 봇 규칙 글(`contract-solo.md`), 켬이면 설치 파일이 지금과 똑같음 · ③ 위키 = 봇 폴더 `.claude/settings.json` 의 «폴더 밖 읽기 허용» 에 그 폴더를 넣음 · ⑦ playwright = 봇 폴더 `.mcp.json` 에 브라우저 서버 1개를 넣고, 봇이 처음 켤 때 «새 MCP 서버» 승인 화면에서 멈추지 않게 같은 폴더 `.claude/settings.json` 에 그 서버 승인 1줄(enabledMcpjsonServers) · ① 창 도구 herdr/tmux/cmux = 봇 설정에 고정 · 나머지(④ ⑤ ⑥ ⑧)는 **고른 값을 기록**하고 점검 표에서 상태를 보여 줍니다(1판은 자동 연결·설치 안 함 — ④ 위키 검색은 연결 안내만).

## 4. 봇
- 가져온 봇(`bot:*` · `slackmod-bot:*`)이 있으면 그 봇들을 봇 목록의 바탕으로 삼습니다(봇 이름 = 소문자·숫자·`-` · 1~32자 · 이름을 고쳐 주기 가능). `source: import`.
- 가져온 봇이 없으면 **역할 기본값 셋**: `lead`(총괄) · `watch`(감시·일정) · `research`(조사). `source: role-default`. 빈 판이면 봇 0개.
- 봇은 **최대 4개**. 작업 폴더 기본 = `~/bots/<이름>`(홈 아래 절대 경로로 풀어 적음).
- **전체 모드**에서는 봇마다 이름·성격 인터뷰를 합니다: `mods-setup:bot-interview` 스킬을 불러 그 질문대로 답을 받고(스킬이 없으면 «건너뜀(아직 없음) — 역할 기본 성격으로 갑니다» 표시), 받은 답은 임시 답 파일에 모읍니다(비밀값 칸 없음). **빠른 모드**는 인터뷰 없이 역할 기본 성격입니다.

## 5. 요약 표 확인 (설치 전 «설치할까요?» 1회)
고른 것을 표 하나로 보여 줍니다: 모드 · 창 도구 · Slack(연결/건너뜀 · 채널 · 손님 수) · 위키 · MCP · 코덱스 · 점검 스킬 · 브라우저 · 메모리 · 하위 세션 쓰기 · 하위 라우터 · 봇(이름 · 역할 · 폴더 · 출처) · 가져올 항목 수. 칸 옆에 «적용» / «기록만» 을 적습니다(위 «이 칸들이 실제로 하는 일»). 그다음 `AskUserQuestion` 으로 **«설치할까요?»** — **설치** / **칸 고치기**(어느 칸인지 묻고 3·4번의 그 칸으로 돌아감) / **그만두기**. 그만두기면 아무것도 쓰지 않았다고 말하고 끝냅니다.

## 6. setup.json 쓰기
고른 결과를 JSON 으로 모아 임시 파일에 쓰고 `python3 -I "$SETUP/lib/plan.py" 임시파일 --out ~/.slackmod/setup.json` 으로 검사·저장합니다(칸 모양은 `plan.py --help`; 비밀값 칸 없음). 출력 줄 중 `  - …` 가 있으면(rc 2) 그 줄대로 고쳐서 다시 — 사용자에게는 쉬운 말로 «어느 칸이 왜 안 되는지»만 전합니다.

## 7. 설치 실행 (확인을 받은 뒤 이 순서)
1. **가져오기 복사** — 가져올 항목이 있으면: `bash "$SETUP/lib/import.sh" --from <id,id,…> --bot <이름>:<작업 폴더> …(봇마다) --to ~/.slackmod/import/<시각>` (가져온 봇의 이름이 새 봇 이름과 다르면 `--map <항목 id>=<새 이름>`). 마지막 두 줄(`결과:` · `원본 지문 전후: 같음`)을 사용자에게 보여 줍니다. `거부` 줄(비밀 꼴 파일)이 있으면 «이 파일은 비밀이 들어 있는 것 같아 복사하지 않았습니다» 라고 알립니다. `오류` 줄에 «바로가기(심볼릭 링크)» 가 나오면 봇 폴더 안의 그 길이 다른 곳을 가리켜 쓰지 않은 것이니, 그 길을 진짜 폴더로 바꾼 뒤 다시 하라고 안내합니다(그 항목만 건너뛰고 나머지는 정상 복사).
2. **성격 파일** — 가져온 봇이 아닌 봇(role-default)의 폴더에 성격 틀을 채웁니다: `bash "$SETUP/lib/optional.sh" persona-fill --answers <답 파일>` (인터뷰 답이 없으면 `{"schema":1,"bots":[{"name":…,"role":…,"dir":…},…]}` 만 담은 파일 — `mktemp` 로 임시 폴더에 만들고 이 단계가 끝나면 지웁니다. `~/.slackmod/` 안에는 남기지 않습니다). 끝 코드 0 = 썼음 · 3 = 이미 있던 다른 파일은 그대로 두었음(«이미 있는 성격 파일은 덮어쓰지 않았습니다» 라고만 알림) · 2 = 입력 문제(그 줄을 전함). «건너뜀(아직 없음)» 이 나오면 그 도구가 아직 없는 것 — 그 줄을 표시하고 성격 틀이 없으면 `bash "$SETUP/lib/role-default.sh" <역할> <봇 폴더>` 로 기본 틀을 복사합니다(그것도 «건너뜀(틀 없음)» 이면 표시하고 진행).
3. **넣기 전 점검** — 봇마다 `bash "$SETUP/lib/optional.sh" persona-check <봇 폴더>`(가져온 봇은 `--skip required` 추가). 끝 코드 1 이면 `걸림 · …` 줄마다 «무엇이 왜 걸렸는지 + 고칠 1줄»을 보여 주고 그 줄대로 고쳐 다시 점검합니다(통과할 때까지, 3번 고쳐도 안 되면 그 봇은 사용자에게 맡기고 «설치는 계속할지» 묻습니다). 「건너뜀(아직 없음)」이면 표시만.
4. **설치** — `bash "$INSTALLER" --plan ~/.slackmod/setup.json` **1회**. 끝 코드는 한 명령으로 같이 받습니다: `bash "$INSTALLER" --plan ~/.slackmod/setup.json; echo "끝 코드=$?"`. 끝 줄 `결과: 바뀜 N · 그대로 M · 지문 …` 을 `결과:` 까지 글자 그대로 보여 줍니다. 끝 코드: 0 성공 · 2 setup 파일/봇 폴더 안의 기존 파일 문제(그 줄을 그대로 전함 — 아무것도 안 바뀐 상태) · 3 먼저 깔 것이 있음(출력된 «깔 줄»을 전함) · 그 밖은 마지막 20줄을 전함. 같은 명령을 두 번 돌려도 «바뀜 0».

## 8. 점검 표
setup.json 의 `doctor` 가 true 일 때: `bash "$SETUP/lib/optional.sh" doctor` — 칸마다 `OK|주의|실패|건너뜀` 한 줄과 맨 끝 `요약: OK n · 주의 n · 실패 n · 건너뜀 n` 을 그대로 보여 줍니다(요약 줄은 지어 쓰지 않습니다). «건너뜀(아직 없음)» 이면 그 표시만. 주의·실패 칸은 고칠 1줄을 같이 전합니다.

## 9. 터미널 열기 (토큰 넣기 · 필수)
Slack 연결을 골랐고 봇이 있으면 **봇마다** `bash "$SETUP/lib/open-terminal.sh" <봇 이름>` — 첫 줄 `OPEN <백엔드> <명령>` 을 글자 그대로 보여 주고(미리 보기일 때도 같음), 새 창이 하는 일 3가지를 알려 줍니다: ① `slackmod set-token`(토큰 두 개, 화면에 안 보임) ② 로그인이 안 돼 있으면 `/login` ③ `slackmod start`. 환경 변수 `MODS_SETUP_NO_OPEN=1` 이 있으면 창을 열지 않고 «미리 보기»만 합니다(시험용). 끝 코드 1(창을 못 엶)이면 출력된 «붙여 넣을 한 줄»을 전합니다. 백엔드가 `none` 이면 «새 터미널을 열고 이 한 줄을 붙여 넣으세요».
Slack 을 건너뛰었거나 빈 판이면 이 단계를 건너뛰고 «나중에 `/mods-setup:setup --section slack` 으로 연결하세요» 라고 합니다.

## 10. 끝 말
무엇이 설치됐는지(경로 대신 이름으로) · 가져온 사본 위치 한 줄 · 점검 요약 줄 · 사용자가 이어서 할 일(열린 창에서 토큰 → 봇 켜기) · 칸 하나만 다시 하려면 `/mods-setup:setup --section <칸>` 을 한 줄로 알립니다.

---

## 답 파일 모드 (`--answers FILE`)
묻지 않습니다(요약 확인도 생략 — 파일이 곧 답). 순서: ① `python3 -I "$SETUP/lib/plan.py" FILE --out ~/.slackmod/setup.json` (빠진 칸은 추천 기본값 · `  - …` 줄이 있으면 그대로 전하고 멈춤) → ② 7번 1~4 그대로(가져오기 = 파일의 `import.from`; 인터뷰 없음) → ③ 8번 → ④ 9번(`MODS_SETUP_NO_OPEN` 이 있으면 미리 보기). 끝 말은 10번.

## 칸 하나 다시 (`--section NAME`)
`~/.slackmod/setup.json` 이 없으면 «먼저 `/mods-setup:setup` 으로 설치하세요» 하고 끝. 있으면 그 칸 질문만 하고(NAME → 3번의 해당 칸 · `bots` = 4번 · `children` = ⑨ · `router` = ⑨-1) 나머지 칸은 그대로 두고, 6번으로 파일을 갱신한 뒤 7번 4(`install.sh --plan`)와 8번만 다시 돌립니다. 바뀐 것이 없으면 «바뀜 0» 이라고 말합니다.
`children`(⑨) · `router`(⑨-1)를 바꿨으면 한 줄 더(`router` 를 동봉 판정기로 켰으면 «`slackmod set-judge-key <봇>` 으로 키 넣기» 도): «봇을 다시 켜야 적용됩니다(`slackmod stop <봇>` → `slackmod start <봇>`) · 끄기 전에 열려 있던 하위 세션은 닫히지 않고 끝 규칙(보고 뒤 · 오래 조용함)대로 닫힙니다 — 바로 닫으려면 끄기 전에 봇에게 «열린 하위 닫아 줘»».
