# MOD 설치 마법사

흐름 = 살펴보기(기록 읽기 미리 안내) → 감지·가져오기 → 모드 → 고르는 칸(+ 추천 스킬 · 작업 폴더 · 생각 깊이 · 쓸 수 있는 모델) → 봇 → 업무 묻기(지금/나중에) → 요약 표 확인 → 설치 회차 기록 시작 → 한 번에 설치 → 점검 표 → 터미널 열기(토큰) · 이어 하기 창(미룬 칸). 사용자는 비개발자일 수 있습니다 — 쉬운 우리말로, 한 번에 한 가지만 묻습니다.

## 먼저 지킬 것
- **토큰·비밀번호는 묻지도 받지도 않습니다.** Bash 도구엔 숨김 입력이 없어서, 토큰은 맨 끝에 열리는 터미널에서 사용자가 직접 넣습니다(`slackmod set-token`). 사용자가 채팅에 토큰을 붙이면 «여기엔 넣지 마세요 — 마지막에 열리는 창에서 넣습니다» 라고 하고 그 값은 어디에도 쓰지 않습니다.
- **다른 에이전트의 원래 설정은 읽기만 합니다.** 가져오기는 «사본»(`~/.slackmod/import/<시각>/` 와 봇 폴더의 프로젝트 범위 `.claude/`)이고, 원본 지문이 전후 같다는 줄을 `import.sh` 가 찍습니다 — 그 줄을 사용자에게 보여 줍니다.
- 질문은 `AskUserQuestion` 한 번에 **질문 4개 이하 · 질문마다 선택지 2~4개**. 자유 입력(채널 ID 등)은 일반 대화로 물어 답을 기다립니다.
- 홈 폴더 밖·`~/.slackmod` 밖(봇 작업 폴더 제외)에는 쓰지 않습니다. `sudo` 는 부르지 않습니다.
- 막히면 이유 한 줄 + 다음에 할 한 줄을 말하고, 막히지 않은 다른 칸은 계속합니다.
- **확인된 것만 말합니다.** «다른 회사 AI 도 쓰실 수 있네요» · «노트 앱 폴더가 있네요» 같은 말은 살펴보기 도구가 실제로 찾은 값으로만 합니다. 모르면 «확인 안 됨»이라고 말합니다.
- **같은 권유는 한 번만.** 사용자가 거절한 추천은 `recommend.declined` 에 남기고 다음 실행에서 다시 권하지 않습니다.
- **플러그인·스킬은 사용자가 고른 것만** 넣습니다. 고르지 않은 것은 설치 줄을 보여 주지도 실행하지도 않습니다.

## 0. 경로 정하기 (처음 한 번)
저장소 폴더 `REPO` 를 정합니다: 환경 변수 `MODS_SETUP_REPO` 가 있으면 그것, 없으면 현재 폴더에서 위로 올라가며 `setup/.claude-plugin/plugin.json` 이 있는 첫 폴더. 그다음 `SETUP=$REPO/setup`, 설치 본체는 `INSTALLER=$(bash "$SETUP/lib/find-installer.sh" "$REPO")`(공개판 `<REPO>/slackmod/install.sh` → 없으면 개발판 `<REPO>/port/install.sh`), 설치 회차 기록 도구는 `RECORD=$(dirname "$INSTALLER")/lib/record.py`. Bash 도구는 호출마다 변수가 사라지므로 **절대 경로를 알아낸 뒤 이후 명령에는 그 절대 경로를 그대로 적습니다.** 못 찾으면 «저장소 폴더에서 `bash install.sh` 로 다시 시작해 주세요» 하고 멈춥니다.

## 인자 읽기
`--answers FILE` → 아래 «답 파일 모드». `--section NAME` → 아래 «칸 하나 다시». `--resume` → 아래 «이어 하기». 셋 다 없으면 0-1번부터.

## 0-1. 살펴보기 (읽기만 · 먼저)
1. **기록 읽기 미리 안내** — `python3 -I "$SETUP/lib/history.py" --notice` 가 내는 문구를 그대로 보여 준 뒤 `AskUserQuestion` «쓰던 대화 기록을 읽어 숫자만 셀까요?» — **읽기(기본 · 추천)** / **읽지 않기**. 고른 값을 `history.read` 로 기억합니다(기본 켬 · 미리 안내 · 끄기 가능).
2. `python3 -I "$SETUP/lib/envscan.py" --home "$HOME"` → 임시 파일 `env.json`. 읽기를 골랐으면 `python3 -I "$SETUP/lib/history.py" --home "$HOME" --days 30` → `history.json`(숫자만 · 글 내용 없음).
3. «찾은 것» 표 한 장(이름으로 · 경로는 꼭 필요한 것만): 컴퓨터 종류(맥·리눅스·WSL) · 명령창 · 창 도구 · Claude Code 버전 · 기본 기억(켜짐/꺼짐/모름) · 노트 앱 폴더 수 · 깔린 스킬·플러그인 수 · 바깥 기억 서비스 흔적(이름만) · (읽었으면) 자주 일한 폴더 위 3개 · 자주 한 일 종류(코드·글·조사·자료). 이 표는 아래 칸들의 «추천값»이 됩니다.
4. `os` 가 Windows 면(윈도우 원본 셸에서 Claude Code 를 연 경우) «봇은 윈도우 안의 리눅스(WSL · Ubuntu)에서 돕니다 — Ubuntu 창을 열고 그 안에서 `bash install.sh` 로 다시 시작해 주세요(WSL 이 없으면 README 의 «Claude Code 먼저 깔기»)» 하고 멈춥니다.

## 1. 감지·가져오기 (먼저)
`bash "$SETUP/lib/detect.sh"` 를 돌려(읽기만) 나온 JSON 의 `items` 를 **마크다운 표**(`| 종류 | 이름 | 짧은 설명 |` · 항목마다 한 줄)로 보여 줍니다. **표는 질문 전에 별도 글로** 실제로 내보냅니다: 표를 응답 본문(글)에 쓰고 «사본으로 가져올까요? 전부 / 고르기 / 안 가져오기 중 하나를 적어 주세요» 한 줄로 그 응답을 **도구 호출 없이 끝냅니다** — 사용자가 적은 글이 이 질문의 답입니다(다음 응답에서 받음 · 같은 것을 다시 묻지 않음 · 뜻이 갈리면 그 한 줄만 다시)(도구를 부르는 응답 안의 글은 화면에 안 나올 수 있음 · 생각(thinking) 안에서만 만든 표는 화면에 나오지 않으므로 보여 준 것이 아닙니다). (`AskUserQuestion` 의 질문·미리 보기 칸이나 명령 출력 안에 넣지 않음 · 생략 금지 · «스킬 2개가 있네요» 같은 문장으로 뭉뚱그리지 않음). 항목이 0개면 «가져올 기존 설정이 없습니다» 하고 2번으로.
답 = **전부 가져오기** / **고르기** / **안 가져오기**(위 표 응답 끝 한 줄에 사용자가 적은 글). 고르기면 그때만 `AskUserQuestion` 으로 항목을 몇 번 묶음으로 나눠 고르게 합니다. 고른 `id` 들을 `import.from` 으로 기억합니다(여기서는 아직 복사하지 않습니다 — 복사는 7번 «설치 실행» 첫 단계).
`skipped` 가 있으면 «읽지 못한 것: …» 한 줄로 알립니다(고치라고 강요하지 않음).

## 2. 모드 3
`AskUserQuestion`: **빠른**(추천 기본값 그대로 · 아래 칸은 Slack 연결 정보와 ⑨ 하위 세션 쓰기 · ⑨-1 하위 라우터만 묻습니다) / **전체**(칸마다 고르기) / **빈 판**(설치 틀만, 봇 0개). 빈 판이면 3번은 «창 도구» 한 칸만 묻고 4·5번(봇)은 건너뜁니다.
**빠른**을 골랐으면 한 번 더 묻습니다 — `AskUserQuestion` «추천 스킬 · 작업 폴더 · 기억도 물어볼까요? (질문이 두세 개 늘어납니다)» — **물어봐 주세요** / **기본값으로**. «물어봐 주세요»면 아래 ⑩ ⑪ 과 ⑧ 기억 칸을 빠른 모드에서도 묻습니다(`quick_ask`). «기본값으로»면 추천 기본 묶음만 넣고 작업 폴더는 «나중에»(`pending` 에 `projects`)로 둡니다.

## 3. 고르는 칸 10개(⑨-1 포함 · 전체 모드 = 세 번에 나눠 묻기)
추천값이 기본입니다(빠른 모드는 아래 «기본» 그대로 두고 ②의 연결 정보와 ⑨ · ⑨-1 만 묻습니다 — 둘은 질문 2개짜리 `AskUserQuestion` 하나).

**첫 번째 묶음(질문 4개)**
- ① 창 도구 — `tmux`(정식·기본 추천) · `cmux`(cmux 창 안에서 tmux) · `herdr`(그 안 tmux + 하위 탭) · `Orca`(시험 중 — «따로 설정하는 안내만» 드립니다, 자동 연결 안 함). 기본 = 자동(고르지 않음).
- ② Slack 연결 — **지금 연결** / **건너뛰기**(나중에 `--section slack`) / **Discord·Telegram·iMessage**(1판은 Slack 만 — 안내만 하고 건너뛴 것으로 처리).
- ③ 위키(노트 앱 폴더) — 살펴보기가 노트 앱 폴더를 찾았으면 **찾은 폴더 잇기**(기본 추천 · 폴더 이름을 보여 줌) / **다른 폴더 지정** / **잇지 않기**. 못 찾았으면 **폴더 지정** / **없음**(기본 — 아래 ⑧ 의 «우리 기본 세팅»이 대신 들어감).
- ④ MCP — **위키 검색** / **없음**(기본).

**두 번째 묶음(질문 4개)**
- ⑤ 코덱스 — **끔**(기본) / **켬**.
- ⑥ 점검 스킬 — **넣음**(기본) / **안 넣음**.
- ⑦ 브라우저 — **playwright**(기본) / **aside** / **안 씀**.
- ⑧ 메모리(기억) — **기본 기억 + 노트 앱 폴더**가 바탕입니다(질문 아님 · 한 줄로 알림): Claude Code 기본 기억이 켜져 있으면 그대로, ③ 에서 이은 폴더가 있으면 봇이 함께 읽습니다. **기억·노트 폴더가 둘 다 없으면** 우리 기본 세팅(빈 노트 폴더 틀 `~/SlackModWiki` + 봇마다 «기억할 것은 여기에» 안내)을 자동으로 넣는다고 알립니다(`memory_setup.starter=true` · 전체 모드에선 «빼기» 가능). 그다음 질문 하나 — 바깥 기억 서비스(인터넷에 기억을 맡겨 두는 서비스 · 회원 가입 필요)를 «이을 수 있게» 할까요: **나중에**(기본) / **Hindsight** / **Kumiho**. 고르면 **연결 시험**을 합니다: `claude mcp list` 출력에 그 이름이 «연결됨»(Connected)으로 있으면 `memory_setup.external_probe="ok"` · 아니면 «아직 연결이 안 돼 있어 저장하지 않습니다 — 그 서비스 안내대로 연결한 뒤 `--section memory`» 하고 `memory`=later · probe=fail(plan.py 가 probe ok 아닌 바깥 기억을 거절 = 시험 실패면 저장 0).

**세 번째 묶음(질문 2개 · 빠른 모드도 이것은 묻습니다)**
- ⑨ 하위 세션 쓰기 — **켬**(기본 추천) / **끔**. 추천 이유 한 줄: «여러 단계 일을 스레드마다 따로 맡기는 것이 이 봇의 기본 방식이고, 지금까지 깔린 봇도 모두 켬으로 돕니다 — 끔은 하위 창을 띄우기 버거운 작은 컴퓨터나 창 하나만 원할 때».
  - 고른 뒤 한 줄로 알립니다. **켬**: «봇이 일 크기를 보고 스스로 하위 세션을 열고, 연 스레드에 «<여는 말>» 한 줄을 남깁니다(여는 말 = 기본 «하위 세션이 맡았어요» · 아래 후속 질문에서 바꿀 수 있음) · 하위를 열게 할 수 있는 사람 = 주인 <②의 사용자 ID, 없으면 «아직 없음 — Slack 연결 때 정함»>(과 허용한 동료 봇) · 손님 글로는 열지 않음 · 주인이 «하위로» 라고 써서 넘기는 말은 이 판에선 아직 안 됨(하위가 스레드에 직접 못 쓰기 때문 — 봇이 일 크기를 보고 엽니다)». **끔**: «봇에 하위 세션 도구(열기·목록·닫기·말 전하기·보드 요약)를 아예 넣지 않고, 모든 일을 봇 본 창에서 합니다 · 하위 세션을 열어 달라는 말엔 «하위 세션 없이 설치됐어요» 라고 답합니다».
  - **켬**이면 후속 둘(**끔**이면 묻지 않음 — 둘 다 쓰이지 않습니다):
    - 주인 ID — 하위를 열게 할 수 있는 사람 = 주인의 Slack 사용자 ID 입니다. ②에서 Slack 을 «지금 연결»로 골랐는데 사용자 ID 가 비어 있으면(`slack.enabled` 참이고 `owner_user_id` 가 빈 상태 — 마법사 도중에만 있는 상태입니다: 저장된 `setup.json` 은 plan.py 를 통과해야 하므로 ID 없이 «연결함» 일 수 없음) **한 번만** 묻습니다: «하위를 열게 할 수 있는 사람(주인)의 Slack 사용자 ID 를 지금 넣을까요? (U 로 시작 · 프로필 ⋯ → 멤버 ID 복사 · 넘기기 가능)». 모양이 틀리면(`^[UW][A-Z0-9]{8,12}$`) 다시 · 넣으면 `slack.owner_user_id`. **넘기면** 위 알림의 «아직 없음 — Slack 연결 때 정함» 그대로이고, plan.py 가 «연결함 + 주인 ID 없음» 을 받지 않으므로 Slack 칸은 건너뛰기(`slack.enabled=false` · `pending` 에 `slack`)로 둡니다 — 이때 화면에 이유 한 줄을 꼭 보여 줍니다: «주인 ID 가 없으면 Slack 연결을 저장할 수 없어서(설치 검사기가 받지 않음) Slack 은 «나중에» 로 둡니다 — 주인 ID 를 알게 되면 `/mods-setup:setup --section slack` 으로 이어서 연결하세요». ②에서 Slack 을 건너뛰었으면 묻지 않습니다(연결 자체가 없음).
    - 여는 말 — `AskUserQuestion` «연 스레드에 남길 한 줄(여는 말)» — **기본 그대로**(첫째 · 추천 · «하위 세션이 맡았어요» 를 선택지에 보여 줌 — 한 번 고르면 끝) / **직접 쓰기**. 직접 쓰기면 한 줄을 받습니다(1~80자 · 한 줄 · « » 못 씀 · 키·토큰처럼 보이는 글 못 씀 — plan.py 가 거부하면 그 이유 한 줄을 알리고 다시). 기본 그대로면 `children_open` 칸을 쓰지 않습니다(`plan.py --normalize` 가 기본 글을 채움). 쓴 글은 `children_open` → 봇 규칙 글 `contract.md` 의 그 한 줄(9번째 줄) «» 안에만 들어갑니다(하위 없는 판의 `contract-solo.md` 는 안 바뀜).
- ⑨-1 하위 라우터(판정 모델이 고름) — **끔**(기본 추천) / **기록만** / **켬**. 이 칸은 늘 보입니다(판정기가 아직 없어도). 한 줄 설명: «주인이 봇에게 쓴 글이 다른 스레드에서 일하는 하위 세션의 일이면, 판정 모델이 그 하위를 골라 줍니다 — 기록만 = 고르기만 하고 기록(아무에게도 안 넘김) · 켬 = 고른 하위에게도 넘김(봇도 그 글을 그대로 받음)».

## 5. 요약 표 확인 (설치 전 «설치할까요?» 1회)
고른 것을 **마크다운 표 하나**(`| 칸 | 고른 것 | 적용/기록만 |` 세 열 · 칸마다 한 줄 · 문단으로 풀어 쓰지 않음)로 보여 줍니다: 모드 · 창 도구 · Slack(연결/건너뜀 · 채널 · 손님 수) · 위키(노트 앱 폴더) · 기억(기본 기억 · 우리 기본 세팅 넣음/안 넣음 · 바깥 기억 서비스와 연결 시험 결과) · 기록 읽기(읽음/안 읽음) · 추천 스킬(더할 것 · 뺀 것) · MCP · 코덱스 · 점검 스킬 · 브라우저 · 하위 세션 쓰기(켬이면 여는 말도 한 줄) · 하위 라우터 · 봇(이름 · 역할 · 폴더 · 이은 작업 폴더 수 · 생각 깊이 · 모델 · 출처) · 업무 묻기(했음/나중에) · 나중에 할 칸(`pending`) · 가져올 항목 수. 칸 옆에 «적용» / «기록만» 을 적습니다(위 «이 칸들이 실제로 하는 일»). **표는 질문 전에 별도 글로** 실제로 내보냅니다: 표를 응답 본문(글)에 쓰고 «설치할까요? 설치 / 고치기 / 그만 중 하나를 적어 주세요» 한 줄로 그 응답을 **도구 호출 없이 끝냅니다** — 사용자가 적은 글이 이 질문의 답입니다(다음 응답에서 받음 · 같은 것을 다시 묻지 않음 · 뜻이 갈리면 그 한 줄만 다시)(도구를 부르는 응답 안의 글은 화면에 안 나올 수 있음 · 생각(thinking) 안에서만 만든 표는 화면에 나오지 않으므로 보여 준 것이 아닙니다). (질문·미리 보기 칸이나 명령 출력 안에 넣지 않음 · 생략 금지). 표를 내보내지 않고 «표로 정리해 보여드렸어요» 같은 말만 하는 것은 금지 — 화면에 표가 없으면 아직 묻지 않습니다. 답(사용자가 적은 글) = **설치** / **칸 고치기**(어느 칸인지 묻고 3·4번의 그 칸으로 돌아감) / **그만두기**. 그만두기면 아무것도 쓰지 않았다고 말하고 끝냅니다.

## 6. setup.json 쓰기
**먼저 7번 0 (설치 회차 기록 시작)을 부릅니다** — 그래야 이번 회차가 만들거나 바꾼 `~/.slackmod/setup.json` 도 `slackmod undo` 로 함께 돌아갑니다(기록이 이 파일을 따로 지켜봄). 이미 이 회차에 불렀으면 다시 부르지 않습니다. 그다음 고른 결과를 JSON 으로 모아 임시 파일에 쓰고 `python3 -I "$SETUP/lib/plan.py" 임시파일 --out ~/.slackmod/setup.json` 으로 검사·저장합니다(칸 모양은 `plan.py --help`; 비밀값 칸 없음). 출력 줄 중 `  - …` 가 있으면(rc 2) 그 줄대로 고쳐서 다시 — 사용자에게는 쉬운 말로 «어느 칸이 왜 안 되는지»만 전합니다. 고치지 못하고 그만두면 `python3 -I "$RECORD" finish --root ~/.slackmod --dir <기록 폴더>` 로 기록을 닫습니다(바뀐 것이 없으면 기록이 남지 않습니다).

## 7. 설치 실행 (확인을 받은 뒤 이 순서)
0. **설치 회차 기록 시작**(6번이 setup.json 을 쓰기 «전»에 — 6번 첫 줄) — `python3 -I "$RECORD" begin --root ~/.slackmod --watch-file ~/.slackmod/setup.json --watch <봇 작업 폴더> …(봇마다)` 를 한 번 부르고(출력 = 기록 폴더 절대 경로 한 줄 · `~/.slackmod/state/installs/` 아래), 그 경로를 이후 명령에 그대로 적습니다. 설치 본체가 쓰기 전에 멈추면(끝 코드 2·3·4) `python3 -I "$RECORD" finish --root ~/.slackmod --dir <기록 폴더>` 로 기록을 닫아 마법사가 이미 쓴 파일도 되돌릴 수 있게 합니다. 이 회차에서 바뀌는 파일(가져오기 사본 · 성격 파일 · 업무 답 · 설치 본체가 쓰는 것 · 우리 기본 세팅)이 모두 이 기록에 남아 `slackmod undo` 로 «방금 설치 하나만» 되돌릴 수 있습니다. 업무를 «지금» 물었으면 lead 봇 폴더에 `work-profile.md` 를 이때 씁니다(이미 있으면 덮지 않고 «이미 있어 그대로 둠»).
1. **가져오기 복사** — 가져올 항목이 있으면: `bash "$SETUP/lib/import.sh" --from <id,id,…> --bot <이름>:<작업 폴더> …(봇마다) --to ~/.slackmod/import/<시각>` (가져온 봇의 이름이 새 봇 이름과 다르면 `--map <항목 id>=<새 이름>`). 마지막 두 줄(`결과:` · `원본 지문 전후: 같음`)을 사용자에게 보여 줍니다. `거부` 줄(비밀 꼴 파일)이 있으면 «이 파일은 비밀이 들어 있는 것 같아 복사하지 않았습니다» 라고 알립니다. `오류` 줄에 «바로가기(심볼릭 링크)» 가 나오면 봇 폴더 안의 그 길이 다른 곳을 가리켜 쓰지 않은 것이니, 그 길을 진짜 폴더로 바꾼 뒤 다시 하라고 안내합니다(그 항목만 건너뛰고 나머지는 정상 복사).
2. **성격 파일** — 가져온 봇이 아닌 봇(role-default)의 폴더에 성격 틀을 채웁니다: `bash "$SETUP/lib/optional.sh" persona-fill --answers <답 파일>` (인터뷰 답이 없으면 `{"schema":1,"bots":[{"name":…,"role":…,"dir":…},…]}` 만 담은 파일 — `mktemp` 로 임시 폴더에 만들고 이 단계가 끝나면 지웁니다. `~/.slackmod/` 안에는 남기지 않습니다). 끝 코드 0 = 썼음 · 3 = 이미 있던 다른 파일은 그대로 두었음(«이미 있는 성격 파일은 덮어쓰지 않았습니다» 라고만 알림) · 2 = 입력 문제(그 줄을 전함). «건너뜀(아직 없음)» 이 나오면 그 도구가 아직 없는 것 — 그 줄을 표시하고 성격 틀이 없으면 `bash "$SETUP/lib/role-default.sh" <역할> <봇 폴더>` 로 기본 틀을 복사합니다(그것도 «건너뜀(틀 없음)» 이면 표시하고 진행).
3. **넣기 전 점검** — 봇마다 `bash "$SETUP/lib/optional.sh" persona-check <봇 폴더>`(가져온 봇은 `--skip required` 추가). 끝 코드 1 이면 `걸림 · …` 줄마다 «무엇이 왜 걸렸는지 + 고칠 1줄»을 보여 주고 그 줄대로 고쳐 다시 점검합니다(통과할 때까지, 3번 고쳐도 안 되면 그 봇은 사용자에게 맡기고 «설치는 계속할지» 묻습니다). 「건너뜀(아직 없음)」이면 표시만.
4. **설치** — `export SLACKMOD_RECORD_DIR=<0번의 기록 폴더>; bash "$INSTALLER" --plan ~/.slackmod/setup.json; echo "끝 코드=$?"` **1회**(한 명령 안에서 · 설치 본체가 끝에 기록을 확정합니다). 끝 줄 `결과: 바뀜 N · 그대로 M · 지문 …` 을 `결과:` 까지 글자 그대로 보여 줍니다. 끝 코드: 0 성공 · 2 setup 파일/봇 폴더 안의 기존 파일 문제(그 줄을 그대로 전함 — 아무것도 안 바뀐 상태) · 3 먼저 깔 것이 있음(출력된 «깔 줄»을 전함) · 그 밖은 마지막 20줄을 전함. 같은 명령을 두 번 돌려도 «바뀜 0».

## 8. 점검 표
setup.json 의 `doctor` 가 true 일 때: `bash "$SETUP/lib/optional.sh" doctor` — 칸마다 `OK|주의|실패|건너뜀` 한 줄과 맨 끝 `요약: OK n · 주의 n · 실패 n · 건너뜀 n` 을 그대로 보여 줍니다(요약 줄은 지어 쓰지 않습니다). «건너뜀(아직 없음)» 이면 그 표시만. 주의·실패 칸은 고칠 1줄을 같이 전합니다.

## 9. 터미널 열기 (토큰 넣기 · 필수)
Slack 연결을 골랐고 봇이 있으면 **봇마다** `bash "$SETUP/lib/open-terminal.sh" <봇 이름>` — 첫 줄 `OPEN <백엔드> <명령>` 을 글자 그대로 보여 주고(미리 보기일 때도 같음), 새 창이 하는 일 3가지를 알려 줍니다: ① `slackmod set-token`(토큰 두 개, 화면에 안 보임) ② 로그인이 안 돼 있으면 `/login` ③ `slackmod start`. 환경 변수 `MODS_SETUP_NO_OPEN=1` 이 있으면 창을 열지 않고 «미리 보기»만 합니다(시험용). 끝 코드 1(창을 못 엶)이면 출력된 «붙여 넣을 한 줄»을 전합니다. 백엔드가 `none` 이면 «새 터미널을 열고 이 한 줄을 붙여 넣으세요».
Slack 을 건너뛰었거나 빈 판이면 이 단계를 건너뛰고 «나중에 `/mods-setup:setup --section slack` 으로 연결하세요» 라고 합니다.

## 9-1. 이어 하기 창 (미룬 칸이 있을 때 · Slack 연결 전에도)
`pending` 이 비어 있지 않으면 `AskUserQuestion` «미뤄 둔 칸(<칸 이름들>)을 봇 폴더에서 이어 할 Claude Code 창을 열까요?» — **지금 열기** / **나중에**. 열기면 `bash "$SETUP/lib/open-terminal.sh" --continue <첫 봇 이름>` — 새 창이 그 봇 폴더에서 Claude Code 를 열고 `/mods-setup:setup --resume` 으로 미룬 칸만 이어 묻습니다(Slack 토큰 없이도 됨). 첫 줄 `OPEN …` 을 글자 그대로 보여 줍니다. 나중에면 «언제든 터미널에서 `bash install.sh --resume`» 한 줄.

## 10. 끝 말
끝 말은 **도구 호출 없는 응답**으로 씁니다(도구를 부르는 응답의 글은 화면에 안 나올 수 있음). 무엇이 설치됐는지(경로 대신 이름으로) · 가져온 사본 위치 한 줄 + 가져오기를 했으면 `import.sh` 마지막 두 줄(`결과:` · `원본 지문 전후: …`)을 글자 그대로 · 점검 요약 줄 · 사용자가 이어서 할 일(열린 창에서 토큰 → 봇 켜기) · 고른 공식 추가 기능의 설치 줄(아직 안 깔았으면) · 칸 하나만 다시 하려면 `/mods-setup:setup --section <칸>` · 미룬 칸이 있으면 `bash install.sh --resume` · **방금 설치를 되돌리려면 터미널에서 `slackmod undo`(무엇이 돌아가는지 먼저 보여 줌) → `slackmod undo --yes` — 설치 뒤 손으로 고친 파일이 있으면 아무것도 안 건드리고 그 목록만 보여 줍니다 · Slack 토큰은 되돌리지 않습니다** 를 한 줄씩 알립니다.

## 답 파일 모드 (`--answers FILE`)
묻지 않습니다(요약 확인도 생략 — 파일이 곧 답). 기록 읽기 안내 문구(`history.py --notice`)는 묻지 않아도 **먼저 한 번 보여 주고**, 파일의 `history.read`(기본 true)대로 읽습니다. 순서: ⓪ 7번 0(기록 시작 · `--watch-file ~/.slackmod/setup.json` 포함) → ① `python3 -I "$SETUP/lib/plan.py" FILE --out ~/.slackmod/setup.json` (빠진 칸은 추천 기본값 · `  - …` 줄이 있으면 그대로 전하고 기록을 닫고(`finish`) 멈춤) → ② 7번 1~4 그대로(가져오기 = 파일의 `import.from`; 인터뷰 없음) → ③ 8번 → ④ 9번(`MODS_SETUP_NO_OPEN` 이 있으면 미리 보기). 끝 말은 10번.

## 칸 하나 다시 (`--section NAME`)
`~/.slackmod/setup.json` 이 없으면 «먼저 `/mods-setup:setup` 으로 설치하세요» 하고 끝. 있으면 그 칸 질문만 하고(NAME → 3번의 해당 칸 · `bots` = 4번 · `children` = ⑨(켬이면 위 후속 둘 — 주인 ID · 여는 말 — 까지) · `router` = ⑨-1) 나머지 칸은 그대로 두고, 6번으로 파일을 갱신한 뒤 7번 4(`install.sh --plan`)와 8번만 다시 돌립니다. 바뀐 것이 없으면 «바뀜 0» 이라고 말합니다.
새 칸 이름: `history`(기록 읽기) · `recommend`(⑩) · `projects`(⑪) · `effort`(⑫) · `models`(⑬) · `work`(업무 묻기) · `memory`(⑧ 기억 · 바깥 기억 연결 시험 포함). 칸을 다시 하면 그 칸 이름을 `pending` 에서 뺍니다. `effort` 를 바꿨으면 «그 봇을 껐다 켜야 적용» 한 줄.
`children`(⑨ · 여는 말 포함) · `router`(⑨-1)를 바꿨으면 한 줄 더(`router` 를 동봉 판정기로 켰으면 «`slackmod set-judge-key <봇>` 으로 키 넣기» 도): «봇을 다시 켜야 적용됩니다(`slackmod stop <봇>` → `slackmod start <봇>`) · 끄기 전에 열려 있던 하위 세션은 닫히지 않고 끝 규칙(보고 뒤 · 오래 조용함)대로 닫힙니다 — 바로 닫으려면 끄기 전에 봇에게 «열린 하위 닫아 줘»».

## 이어 하기 (`--resume`)
`~/.slackmod/setup.json` 이 없으면 «먼저 `/mods-setup:setup` 으로 설치하세요» 하고 끝. 있으면 먼저 `python3 -I "$SETUP/lib/plan.py" ~/.slackmod/setup.json` 으로 검사합니다(파일을 직접 열어 고치지 않음) — rc 2 면 그 줄을 쉬운 말로 전하고 `AskUserQuestion` «처음부터 다시 / 그만두기»(어느 쪽이든 그 파일은 지우지 않고, 처음부터면 새 답으로 6번이 덮어씀). 통과하면 `pending` 을 읽어 적힌 순서대로 그 칸만 «칸 하나 다시»처럼 묻습니다(`work` = 4-1 업무 묻기 · `projects` = ⑪ · `recommend` = ⑩ · `models` = ⑬ · `memory` = ⑧ · `slack` = ② · `effort` = ⑫). 끝나면 `pending` 에서 지우고 6번 → 7번 0·4(새 설치 회차) → 8번. `pending` 이 비어 있으면 «이어 할 칸이 없습니다» 하고 끝. 이어 하기 창(9-1)에서 열렸으면 끝에 «이 창은 /exit 로 닫으세요».
